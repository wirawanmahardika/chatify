# Chatify Project Guidelines

Chatify is a real-time chat web application built with **Bun**, **Elysia**, **PostgreSQL**, **Drizzle ORM**, **Zod**, **HTMX v4**, **Alpine.js**, and **Tailwind CSS v4 + DaisyUI v5** using server-rendered JSX.

## Tech Stack

- **Runtime**: Bun
- **Web Framework**: Elysia (`elysia`, `@elysiajs/html`, `@elysia/static`)
- **Database**: PostgreSQL + Drizzle ORM (`drizzle-orm`, `drizzle-kit`)
- **Validation & Config**: **Zod** exclusively (`zod` for environment configuration in `src/config.ts`, request/domain validation, and Drizzle schema validation)
- **Frontend**: Server-rendered JSX (`@kitajs/html`), **HTMX v4** (via package manager), **Alpine.js** (via package manager), Tailwind CSS v4 + DaisyUI v5

## Project Structure

- `src/index.ts` — Application entrypoint, cookie/HTML/static setup, and module registration
- `src/config.ts` — Validated environment variables (`config` / `env`)
- `src/modules/<feature>/` — Feature modules (`auth`, `chat`, etc.):
  - `index.ts` — Elysia routes and WebSocket handlers
  - `model.ts` — Zod schemas (`z`) and inferred TypeScript types (`z.infer<typeof ...>`)
  - `service.ts` — Business logic and Drizzle database queries
  - `views.tsx` — JSX pages and HTMX partial components
- `src/shared/` — Shared PostgreSQL schema/client (`db.ts`), utilities (`idGenerator.ts`), app layout (`views/layout.tsx`), and cross-feature UI components (`components/*.tsx`)
- `public/` — Static assets, custom client scripts (`public/js/`), `input.css`, and compiled `style.css`
- `drizzle/` — Generated Drizzle SQL migrations and snapshots

## Development Commands

- `bun run dev` — Start the Elysia server in watch mode
- `bun run tailwind` — Watch and compile `public/input.css` to `public/style.css`
- `bun run build` — Build minified Tailwind CSS output

## Core Rules

1. **Follow the module pattern**: New features belong in `src/modules/<feature>/` separated into `index.ts`, `model.ts`, `service.ts`, and `views.tsx`.
2. **Keep routes thin**: `index.ts` handles HTTP/WebSocket routing, cookies, headers (e.g., `HX-Redirect`), and input validation; delegate business logic and DB queries to `service.ts`.
3. **Database & Validation**: Use **PostgreSQL** with `drizzle-orm` (defined in `src/shared/db.ts`, migrated via `drizzle/`) and **Zod** exclusively for all validation—pair Drizzle ORM with Zod validation whenever possible.
4. **HTMX v4 First**: Use **HTMX v4** and **Alpine.js** from the package manager. Exhaust all built-in HTMX v4 features before introducing Alpine.js or other client-side libraries, and only use them when HTMX v4 does not provide the needed capability.
5. **Language**: All user-facing UI text, validation messages, and error messages must be written in **Indonesian**.
6. **Generated files**: Do not manually edit `public/style.css` (generated by Tailwind CLI).
